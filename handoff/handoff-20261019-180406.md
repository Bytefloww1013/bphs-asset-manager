## Goal
Run a live test of the handoff guard's auto-start after `clear_session("self")`.
- **Why the user wants it:** long, unattended coding runs that go for hours or overnight. A context that sits idle after each clear makes those pointless.
- **What this test checks:** whether the next context starts on its own, with no typing from the user.

## Done
- Autocompact for Opus is back at 200k (the user ran `/autocompact 200000`), which is above `HANDOFF_AT` (175k).
- Research findings (sources are in the previous context's last reply):
  - `initialUserMessage` is documented only for non-interactive `-p` runs. The desktop app runs the CLI in non-interactive streaming mode (`--input-format stream-json`), so it should apply. This test settles it.
  - Fallback design, from hex/claude-sessions (github.com/hex/claude-sessions/blob/main/docs/hooks.md):
    1. On `clear`, the SessionStart hook sets `watchPaths` on a kick folder and starts a detached helper.
    2. A few seconds later the helper writes a kick file.
    3. That write fires a `FileChanged` hook with `asyncRewake: true`, which exits 2 and so wakes Claude with a "resume from handoff" reason.
    4. A "delivered" marker allows only one wake per clear, and the helper retries up to 30 times.
  - The bundled CLI (2.1.299) supports `asyncRewake`.
- The guard was set to pending by hand for this test.
